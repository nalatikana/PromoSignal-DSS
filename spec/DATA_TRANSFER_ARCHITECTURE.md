# สถาปัตยกรรมการส่งข้อมูลระหว่างทีมสถิติกับทีมเว็บ
### PromoSignal DSS · ฉบับเสนอที่ประชุม · 23 สิงหาคม 2569

---

## 1. ปัญหาที่ต้องแก้

ที่ประชุมวันที่ 19 สิงหาคม สรุปว่าโมเดลชุดใหม่จะฟิตด้วย **R หรือ Stata** เปลี่ยนตัวแปรตามเป็น
**Innovation Intensity** ที่คำนวณจาก Wording Ratios และใช้ตัวแปรอิสระ **8 ตัว** ซึ่งจะยืนยันชื่อภายในวันจันทร์

คำถามที่ตามมาคือ **โมเดลที่ฟิตใน R จะไปโผล่บนเว็บได้อย่างไร** โดยที่

1. ทีมเว็บไม่ต้องแก้โค้ดใหม่ทุกครั้งที่โมเดลเปลี่ยน
2. **ข้อมูลดิบไม่ออกจากเครื่องทีมสถิติ** — มีชื่อบริษัท ชื่อกรรมการ ชื่อ CEO อยู่ในนั้น
3. ไม่ต้องซื้อเซิร์ฟเวอร์

## 2. สามทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย | ตัดสิน |
|---|---|---|---|
| **ก. ส่งข้อมูลดิบให้ทีมเว็บฟิตใหม่ใน Python** | ควบคุมได้เต็มที่ | ข้อมูลรายบริษัทต้องออกจากเครื่อง · ผลอาจไม่ตรงกับที่ทีมสถิติรายงาน · ทำซ้ำทุกครั้งที่โมเดลเปลี่ยน | ❌ |
| **ข. ตั้งเซิร์ฟเวอร์ที่รัน R แล้วให้เว็บเรียก API** | โมเดลสดตลอด | ต้องมีเซิร์ฟเวอร์ · ค่าใช้จ่ายและงานดูแลต่อเนื่อง · ไฟล์ผู้ใช้ต้องอัปโหลดขึ้นไป ผูกภาระ PDPA | ❌ ยังไม่จำเป็น |
| **ค. ไฟล์สัญญาโมเดล (model contract)** | ไม่มีข้อมูลดิบเลย · ไม่ต้องมีเซิร์ฟเวอร์ · ทีมเว็บไม่ต้องแก้โค้ด · ตรวจสอบย้อนหลังได้เพราะเป็นไฟล์ที่เก็บไว้ได้ | ไม่ใช่โมเดลสด ต้องส่งไฟล์ใหม่เมื่อฟิตใหม่ | ✅ **เลือกทางนี้** |

## 3. หลักการของทางเลือก ค

โมเดลถดถอยหนึ่งตัวไม่ได้ต้องการข้อมูลดิบเพื่อทำนาย มันต้องการแค่

- **สัมประสิทธิ์** (coefficients) — ตัวเลขไม่กี่สิบตัว
- **เมทริกซ์ความแปรปรวนร่วม** (variance–covariance matrix) — ใช้คำนวณช่วงความเชื่อมั่น
- **ค่ากลางที่ใช้ mean-center** — เพื่อให้เว็บลบค่าถูกก่อนคูณ
- **ค่าฐานรายปีและรายอุตสาหกรรม** (fixed effects)
- **α** ของ Negative Binomial — ใช้คำนวณช่วงพยากรณ์ค่าจริง

ทั้งหมดนี้เป็น**ตัวเลขสรุป** ไม่มีชื่อบริษัท ไม่มีชื่อบุคคล ไม่มีแถวข้อมูลรายบริษัทอยู่เลย
ย้อนกลับไปหาข้อมูลดิบไม่ได้ จึงส่งข้ามทีมได้อย่างปลอดภัย

```
   ทีมสถิติ (เครื่องตัวเอง)                          ทีมเว็บ / ผู้ใช้
   ┌───────────────────────┐                        ┌───────────────────────┐
   │ panel_clean.csv       │                        │ PromoSignal_DSS.html  │
   │ (มีชื่อบริษัท/บุคคล)   │                        │ (ไฟล์เดียว ไม่มีเซิร์ฟเวอร์)│
   │          │            │      model.json        │          ▲            │
   │          ▼            │   ── ตัวเลขสรุป ──▶     │          │            │
   │ R: glm.nb / Stata:    │   ไม่มีข้อมูลรายบริษัท   │  ลากไฟล์เข้าแท็บ      │
   │ nbreg                 │                        │  "ข้อมูลและโมเดล"      │
   │          │            │                        │          │            │
   │          ▼            │                        │          ▼            │
   │ export_model.R / .do  │                        │ ตรวจไฟล์ → ติดตั้ง →    │

                                                    └───────────────────────┘
```

## 4. รูปแบบไฟล์ — `promosignal-model/1`

ข้อกำหนดฉบับเต็มอยู่ที่ `spec/model_contract.schema.json` (JSON Schema draft 2020-12)
ตัวอย่างไฟล์จริงที่ใช้งานได้อยู่ที่ `spec/example_model.json`

| คีย์ | บังคับ | ความหมาย |
|---|:--:|---|
| `schema` | ✅ | ต้องเป็น `"promosignal-model/1"` เสมอ |
| `name` · `key` | ✅ | ชื่อที่แสดงบนปุ่มสลับชุดโมเดล |
| `target` | ✅ | ตัวแปรตาม + `family` (`negbin` / `poisson`) + `scale` (`count` / `rate`) |
| `alpha` | ✅ (ถ้า negbin) | ค่าการกระจายเกินแบบ NB2 · **R ให้ `1/theta` · Stata ให้ `exp(lnalpha)`** |
| `intercept` | ✅ | ค่าคงที่บนสเกล log |
| `variables[]` | ✅ | ทุกตัวแปรที่ผู้ใช้ปรับได้ พร้อม `center` · `sd` · ช่วง min–max · หน่วย · เป็นตัวแปรควบคุมหรือไม่ |
| `terms[]` | ✅ | พจน์ในสมการ · ปฏิสัมพันธ์เขียน `"a:b"` |
| `coef` · `se` · `p` | `coef` ✅ | สัมประสิทธิ์ ค่าคลาดเคลื่อน และค่า p ต่อพจน์ |
| `vcov` | ✅ | `order` ต้องขึ้นต้นด้วย `"Intercept"` · `matrix` เป็นเมทริกซ์จัตุรัสขนาดเท่ากัน |
| `fixed_effects` | — | ค่าฐานรายปีและรายอุตสาหกรรม · กลุ่มฐานใส่ 0 |
| `fit` · `oos` | — | สถิติความพอดีและผลทดสอบนอกกลุ่มตัวอย่าง |
| `reference` | — | การกระจายของค่าจริง ใช้จัดอันดับเปอร์เซ็นไทล์ ถ้าไม่มีระบบใช้ของชุดเดิม |
| `notes` | — | ข้อจำกัดที่ต้องแสดงคู่กับผลลัพธ์ทุกครั้ง |

## 5. เครื่องมือที่ทำไว้ให้แล้ว

| ไฟล์ | สำหรับ | ต้องแก้อะไร |
|---|---|---|
| `spec/export_model.R` | R + `MASS::glm.nb` | แก้บล็อก "ตั้งค่า" ด้านบน — ชื่อไฟล์ ตัวแปรตาม รายชื่อ 8 ตัวแปร ป้ายภาษาไทย |
| `spec/export_model.do` | Stata + `nbreg` | แก้ `local` ด้านบนแบบเดียวกัน |

ทั้งสี่ไฟล์ดาวน์โหลดได้จากในเว็บโดยตรง — แท็บ **ข้อมูลและโมเดล → หัวข้อ 2**

## 6. การตรวจไฟล์ก่อนติดตั้ง

เว็บตรวจ **8 เรื่อง** ก่อนยอมเปลี่ยนโมเดล ถ้าไม่ผ่านแม้ข้อเดียว **จะไม่เปลี่ยนอะไรเลย**
และแสดงรายการที่ผิดเป็นภาษาไทยทีละข้อ

1. `schema` ตรงรุ่นที่รองรับ
2. คีย์บังคับครบ
3. ทุกพจน์ใน `terms` อ้างถึงตัวแปรที่ประกาศไว้จริง
4. ทุกพจน์มีสัมประสิทธิ์
5. ทุกตัวแปรมีค่า `center`
6. `vcov.order` ขึ้นต้นด้วย `Intercept`
7. ขนาดของ `vcov.matrix` ตรงกับ `vcov.order` ทั้งแถวและคอลัมน์
8. ถ้าเป็น negbin ต้องมี `alpha` มากกว่าศูนย์

## 7. การยืนยันว่าคำนวณตรงกัน (ทำแล้ว)

แปลงชุดโมเดล B ที่ฝังอยู่ในเว็บให้อยู่ในรูปไฟล์สัญญา แล้วโหลดกลับเข้าไปใหม่
ค่าคาดการณ์ของหลักทรัพย์ทดสอบทั้ง 6 รายการ **ตรงกันทุกตำแหน่งทศนิยม**
(3.23 · 1.46 · 1.42 · 1.41 · 1.12 · 0.49) ยืนยันว่าเส้นทางส่งข้อมูลไม่ทำให้ตัวเลขเพี้ยน

## 8. ข้อจำกัดที่ต้องรู้

- **ระบบตรวจสอบตัวเลข `oos` เองไม่ได้** เพราะไม่มีข้อมูลดิบ — ต้องเชื่อผู้ส่งไฟล์
  รายงานจึงต้องระบุเสมอว่า *ใครฟิต ฟิตเมื่อไหร่ ด้วยชุดข้อมูลไหน*
- ผลทดสอบย้อนหลังแบบเลื่อนจุดตั้งต้นในแท็บ "ทดสอบย้อนหลัง 5 ปี" **ทำได้เฉพาะชุดโมเดล A และ B**
  ที่ระบบฟิตเองจากข้อมูลดิบ ชุดที่โหลดเข้ามาจะแสดงเฉพาะตัวเลขที่แนบมาในไฟล์
- ไฟล์สัญญาไม่รองรับโมเดลที่มี random effects หรือ multilevel — ถ้าจำเป็นต้องขยายรุ่นเป็น `promosignal-model/2`
- ตัวแปรที่เป็น factor หลายระดับ (นอกจากปีและอุตสาหกรรม) ยังไม่รองรับ ต้องแปลงเป็น dummy เอง

## 9. สิ่งที่รอจากคุณปูลม

1. **ชื่อตัวแปรอิสระทั้ง 8 ตัว** พร้อมหน่วยและช่วงค่าที่พบจริง
2. **นิยามของ Innovation Intensity** — คำนวณจาก Wording Ratios ด้วยสูตรใด และหน่วยเป็นอะไร
   (ถ้าเป็นอัตราส่วนไม่ใช่จำนวนนับ ต้องตั้ง `target.scale = "rate"` เพื่อให้เว็บปิดช่วงพยากรณ์แบบจำนวนเต็ม)
3. **ยืนยันว่าใช้แฟ้มข้อมูลฉบับไหน** — ผลตรวจล่าสุดพบบริษัทที่ข้อมูลครบ 5 ปี **142 บริษัท** ไม่ใช่ 122
   และ **ไม่พบความผิดปกติเชิงโครงสร้าง**ของตัวแปร Political / Military ตามที่ที่ประชุมระบุ
