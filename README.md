# PromoSignal DSS

ต้นแบบระบบสนับสนุนการตัดสินใจ — ทำนายจำนวน **นวัตกรรมเปิด** (พันธมิตร / JV / MOU) จากภาษาผู้บริหารและโครงสร้างคณะกรรมการ

**รุ่น 2 · ปรับตามมติที่ประชุม 19 สิงหาคม 2569 — สองโหมดในลิงก์เดียว**

| โหมด | ขั้นตอน |
|---|---|
| **ประเมินองค์กร** | อัปโหลดเอกสาร → โมเดลวิเคราะห์ (Board-Fit Simulator) → แดชบอร์ดและรายงาน |
| **คัดหุ้นลงทุน** | เรตติ้ง A–E · คะแนนเติบโต · วิเคราะห์ความอ่อนไหว → ทดสอบย้อนหลัง 5 ปี |

พร้อมแท็บ **ข้อมูลและโมเดล** ที่ใช้ร่วมกันทั้งสองโหมด — เสียบโมเดลจาก R หรือ Stata ได้โดยไม่ต้องแก้โค้ด
และติดตามความคืบหน้าของข้อมูลตรวจสอบ 420 เรคคอร์ด

| ในขอบเขต | นอกขอบเขต |
|---|---|
| score · ranking · board-fit simulator · เรตติ้งหุ้น · ทดสอบย้อนหลัง · ช่องเสียบโมเดล · export รายงาน | ระบบ production · บัญชีผู้ใช้ · การเชื่อมข้อมูลสด |

## 🔌 เสียบโมเดลจาก R หรือ Stata (ใหม่ในรุ่น 2)

โมเดลที่ทีมสถิติฟิตด้วย R หรือ Stata ใช้บนเว็บได้ทันที **โดยไม่ต้องส่งข้อมูลดิบออกจากเครื่อง**
และ **ไม่ต้องมีเซิร์ฟเวอร์**

```
ทีมสถิติ                                     เว็บแอป
panel_clean.csv  ──▶  export_model.R  ──▶  model.json  ──▶  ลากเข้าแท็บ "ข้อมูลและโมเดล"
(มีชื่อบริษัท)         หรือ export_model.do   (ตัวเลขสรุป)      ทุกหน้าจอใช้สมการใหม่ทันที
```

ไฟล์สัญญาบรรจุเฉพาะสัมประสิทธิ์ · เมทริกซ์ความแปรปรวนร่วม · ค่ากลาง · ค่าฐานรายปี/อุตสาหกรรม · α
**ไม่มีชื่อบริษัท ไม่มีชื่อบุคคล ไม่มีแถวข้อมูลรายบริษัท** ย้อนกลับไปหาข้อมูลดิบไม่ได้

| ไฟล์ | คำอธิบาย |
|---|---|
| [`spec/model_contract.schema.json`](spec/model_contract.schema.json) | ข้อกำหนดไฟล์ `promosignal-model/1` (JSON Schema) |
| [`spec/export_model.R`](spec/export_model.R) | สคริปต์ส่งออกจาก R (`MASS::glm.nb`) — แก้บล็อก "ตั้งค่า" ด้านบนเท่านั้น |
| [`spec/export_model.do`](spec/export_model.do) | สคริปต์ส่งออกจาก Stata (`nbreg`) |

| [`spec/DATA_TRANSFER_ARCHITECTURE.md`](spec/DATA_TRANSFER_ARCHITECTURE.md) | เอกสารสถาปัตยกรรมการส่งข้อมูลระหว่างทีม |

ทั้งหมดดาวน์โหลดได้จากในเว็บโดยตรงที่แท็บ **ข้อมูลและโมเดล → หัวข้อ 2**

ระบบตรวจไฟล์ 8 ข้อก่อนติดตั้ง ถ้าไม่ผ่านแม้ข้อเดียวจะ**ไม่เปลี่ยนอะไรเลย**
ยืนยันความถูกต้องแล้วด้วยการแปลงชุดโมเดล B เป็นไฟล์สัญญาแล้วโหลดกลับ — ค่าคาดการณ์ตรงกันทุกตำแหน่งทศนิยม

## 📈 ทดสอบย้อนหลัง 5 ปี (ใหม่ในรุ่น 2)

เทรนด้วยข้อมูลถึงปี t แล้วทดสอบกับปี t+1 ที่โมเดลไม่เคยเห็น เลื่อนไปทีละปี (rolling origin)

| ตัวชี้วัด (เฉลี่ย 3 รอบ) | ชุดโมเดล A | ชุดโมเดล B | อ่านว่า |
|---|---:|---:|---|
| c-index | 0.630 | **0.669** | เลือกคู่ใดมาสองบริษัท บอกถูกว่าใครมีนวัตกรรมเปิดมากกว่า 67 ครั้งจาก 100 |
| Spearman | 0.298 | **0.382** | อันดับที่ทายกับอันดับจริงไปด้วยกันปานกลาง |
| MASE | 1.139 | **1.127** | ⚠️ ยัง **มากกว่า 1** — ทายจำนวนสู้การใช้ตัวเลขปีที่แล้วไม่ได้ |
| ส่วนต่างควินไทล์ | 1.873 | **1.965** | กลุ่มบนมีนวัตกรรมเปิดจริงมากกว่ากลุ่มล่าง ~2 รายการ/ปี |

**ข้อสรุปที่ซื่อตรง** — ชุดโมเดล B ชนะ A ทุกตัวชี้วัดในทุกรอบ แต่ระบบนี้เป็นเครื่องมือ**จัดอันดับ** ไม่ใช่เครื่องทำนายจำนวน
ระบบแสดง MASE ให้ผู้ใช้เห็นตรง ๆ ในหน้าจอ ไม่ได้ซ่อนไว้

## 🗂 สถานะข้อมูล

ตรวจ `panel_clean.csv` เมื่อ 23 สิงหาคม 2569 พบสองเรื่องที่**ไม่ตรงกับบันทึกการประชุม**

1. **บริษัทที่ข้อมูลครบ 5 ปี = 142 บริษัท** (ไม่ใช่ 122) และตัวเลขเท่ากันไม่ว่าจะนับด้วย 8 · 12 หรือ 17 ตัวแปร
   → ข้อจำกัดคือทั้งแถวหายพร้อมกัน ไม่ใช่ตัวแปรใดตัวแปรหนึ่งหายเป็นจุด ๆ
2. **ไม่พบความผิดปกติเชิงโครงสร้างของ Political / Military** — ไม่มีแถวใดที่จำนวนกรรมการเกินขนาดบอร์ด
   ไม่มีค่าติดลบ ไม่มีค่าที่ไม่ใช่จำนวนเต็ม · มีเพียงข้อมูลขาด 56 แถว (5.3%) ซึ่งเป็นแถวชุดเดียวกับตัวแปรบอร์ดอื่น

รายละเอียดทั้งหมดดูได้ในแท็บ **ข้อมูลและโมเดล → หัวข้อ 4** พร้อมดาวน์โหลดแม่แบบเก็บข้อมูล 420 เรคคอร์ด

**สาเหตุที่เป็นไปได้**

- นิยามตัวแปรตามต่างกัน — ค่าเฉลี่ยของเขา ~6.7 · พันธมิตรในชุดนี้ 1.46 · นวัตกรรมรวม 9.24

## 🧮 คณิตศาสตร์ที่ใช้

```
E[OI]  = exp( β₀ + Σ βₖ·(xₖ − x̄ₖ) + FE(อุตสาหกรรม) + FE(ปี) )
Var(η) = xᵀ · V · x     →     95% CI ของค่าเฉลี่ย = exp( η ± 1.96·√Var(η) )
90% ช่วงพยากรณ์ค่าจริง  = ควอนไทล์ที่ 5 และ 95 ของ NegBinom(μ, α)
```

- **Negative Binomial** — ตัวแปรตามเป็นข้อมูลนับ มีศูนย์ 46% และกระจายเกิน (α ≈ 1.09–1.17)
- ตัวแปรทุกตัว **mean-center** ก่อนเข้าสมการ → ตีความ main effect ได้ตรงแม้มี interaction
- **CI ของค่าเฉลี่ย** ≠ **ช่วงพยากรณ์ค่าจริง** — ระบบแสดงทั้งสองแยกกัน เพราะตอบคนละคำถาม
- เตือนอัตโนมัติเมื่อค่าที่กรอกอยู่นอกเปอร์เซ็นไทล์ 5–95 ของข้อมูลจริง (กัน extrapolation)

### ความแม่นจากการทดสอบนอกกลุ่มตัวอย่าง (391 บริษัท-ปี)

| ตัวชี้วัด | ชุดโมเดล A | ชุดโมเดล B | อ่านอย่างไร |
|---|---|---|---|
| Spearman | 0.260 | **0.342** | ความแม่นของการจัดอันดับ |
| c-index | 0.612 | **0.650** | 0.5 = เดาสุ่ม · 1.0 = สมบูรณ์แบบ |
| MASE | 1.090 | **1.076** | ≥ 1 = **ยังไม่ชนะการเดาด้วยค่าปีก่อน** |
| ช่วงพยากรณ์ 90% ครอบคลุมจริง | 95.4% | 94.9% | ใกล้ 90% = ช่วงตั้งไว้พอดี |

> **อ่านตรง ๆ:** MASE ≥ 1 แปลว่าโมเดลยังทำนาย "จำนวน" ได้ไม่แม่นกว่าการเดาด้วยค่าปีก่อนของบริษัทเดียวกัน
> จุดแข็งอยู่ที่การ **จัดอันดับ** (c-index 0.65) ไม่ใช่การทำนายจำนวนที่แม่นยำ — ระบบแสดงข้อความนี้ให้ผู้ใช้เห็นเสมอ

## 🔒 ความเป็นส่วนตัวและข้อจำกัด

1. **ไม่ใช่ความสัมพันธ์เชิงสาเหตุ** — โมเดลบอกว่าบริษัทที่มีโครงสร้างแบบนี้มักมีนวัตกรรมเปิดเท่าไร ไม่ได้บอกว่าเปลี่ยนโครงสร้างแล้วจะได้ผลตามนั้น
2. **วัดการประกาศ ไม่ใช่นวัตกรรมจริง** — ตัวแปรตามนับจากข้อความในรายงานประจำปี
3. **เอกสารฉบับเดียวกัน** — ภาษาผู้บริหารและจำนวนนวัตกรรมมาจากรายงานฉบับเดียวกัน มีความเสี่ยง endogeneity ที่ยังไม่ได้แก้
4. **ห้ามใช้ให้คะแนนบุคคล** — เพศ อายุ และความเชื่อมโยงทางการเมือง เป็นข้อมูลอ่อนไหวตาม **PDPA มาตรา 26** ระบบออกแบบให้ประเมิน**โครงสร้างองค์กร** ไม่ใช่ประเมินตัวบุคคล
5. **ไฟล์ที่อัปโหลดไม่ถูกส่งออกนอกเครื่อง** — อ่านด้วย pdf.js ในเบราว์เซอร์เท่านั้น
6. **ฐานข้อมูลอ้างอิงปกปิดชื่อทั้งหมด** — สแกนแล้ว ไม่มีชื่อบริษัทหรือชื่อบุคคลในไฟล์ใด
7. `.gitignore` กันไฟล์ข้อมูลดิบและตารางถอดรหัสไม่ให้ถูก commit โดยไม่ตั้งใจ
