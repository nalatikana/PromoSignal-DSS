# PromoSignal DSS

ต้นแบบระบบสนับสนุนการตัดสินใจ — ทำนายจำนวน **นวัตกรรมเปิด** (พันธมิตร / JV / MOU) จากภาษาผู้บริหารและโครงสร้างคณะกรรมการ

**3 ขั้นตอน:** อัปโหลดเอกสาร → โมเดลวิเคราะห์ (Board-Fit Simulator) → แดชบอร์ดและรายงาน

| ในขอบเขต | นอกขอบเขต |
|---|---|
| score · ranking · board-fit simulator · export รายงาน | ระบบ production · บัญชีผู้ใช้ · การเชื่อมข้อมูลสด |

## 🚀 เปิดใช้งาน

### วิธีที่ 1 — เปิดไฟล์เดียว (ไม่ต้องติดตั้งอะไร)

ดับเบิลคลิก `docs/index.html` — ใช้ได้กับเบราว์เซอร์ทุกตัว ทุกอย่างทำงานในเครื่อง ไม่ส่งข้อมูลออก

### วิธีที่ 2 — เผยแพร่ผ่าน GitHub Pages

1. เปิด **GitHub Desktop** → `File` → `Add Local Repository` → เลือกโฟลเดอร์นี้
2. ใส่ Summary แล้วกด **Commit to main** → กด **Publish repository**
   (จะตั้งเป็น Private ก็ได้ แต่ Pages ต้องใช้ Public หรือบัญชี GitHub Pro)
3. บนเว็บ GitHub → `Settings` → `Pages` → Source: **Deploy from a branch**
   → Branch: `main` · Folder: **`/docs`** → `Save`
4. รอ ~1 นาที เว็บจะขึ้นที่ `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

ไม่ต้องใช้ GitHub Actions — วิธีนี้ง่ายกว่าและเสิร์ฟจากโฟลเดอร์ `docs/` โดยตรง
ทุกครั้งที่ push ไฟล์ใหม่เข้า `docs/` เว็บจะอัปเดตเองภายในไม่กี่นาที

ระบบมีชุดโมเดล 2 ชุดให้สลับดูได้ เพราะสเปกตั้งต้นกับผลที่รันได้จริง **ไม่ตรงกัน**

| | ชุดโมเดล A | ชุดโมเดล B ⭐ |
|---|---|---|
| ที่มา | ตามสเปกใน `Pitch2.pptx` | ตามผลที่รันได้จริง |
| ตัวขยายผล | Promo×%Female · Promo×PolTie | — |
| มีนัยสำคัญไหม | **ไม่** (p = 0.802 · 0.267) | อายุงานบอร์ด **p = 0.001** · กรรมการอิสระ **p = 0.001** · ขนาดบอร์ด **p = 0.006** |
| α (overdispersion) | 1.166 | 1.089 |
| จำนวนเทอม | 21 | 22 |
| Spearman (จัดอันดับ) | 0.260 | **0.342** |
| c-index | 0.612 | **0.650** |

**สเปกใน `Pitch2.pptx` เขียนว่า** _"β₄, β₅ > 0 และ significant → Simulator ใช้สองตัวนี้ขยายผลได้อย่างมั่นใจ"_
เมื่อรันกับข้อมูลจริง 900 บริษัท-ปี เงื่อนไขนี้ **ไม่เป็นจริง**

**ทดสอบได้เองในระบบ** — บอร์ด 2 ชุดที่ต่างกันมาก (อายุงานเฉลี่ย 5 ปี vs 18 ปี · กรรมการอิสระ 50% vs 30%):

| | ชุดโมเดล A | ชุดโมเดล B |
|---|---|---|
| บอร์ดชุดที่ 1 | 1.82 | **2.40** |
| บอร์ดชุดที่ 2 | 1.82 | **1.16** |
| แยกความต่างได้ไหม | **ไม่ได้เลย** — ค่าเท่ากันเป๊ะ | ได้ชัด ต่างกัน 2 เท่า |

ชุดโมเดล A ไม่มีตัวแปรอายุงานบอร์ดและกรรมการอิสระอยู่ในสมการ จึงให้ค่าเท่ากันแม้บอร์ดต่างกันสิ้นเชิง

## ⚠️ หมายเหตุการเทียบกับโมเดลอีกชุด

โมเดลอีกชุดที่ทีมได้รับ รายงาน **Political × Promotion IRR = 2.09 (p = .005)**

ชุดข้อมูลนี้ทดสอบ **6 สเปก** แล้วได้ IRR **0.70–0.86** (p = 0.06–0.28) — **ทิศทางตรงข้ามกัน**

| สเปกที่ทดสอบ | IRR | p |
|---|---|---|
| n_partners + FE ปี/อุตสาหกรรม | 0.704 | 0.209 |
| innov_total + FE ปี/อุตสาหกรรม | 0.770 | 0.213 |
| n_partners + year trend + industry factor | 0.699 | 0.199 |
| innov_total + year trend + industry factor | 0.790 | 0.261 |
| political = นับคน (peps_bod) | 0.727 | 0.064 |
| political = สัดส่วนต่อขนาดบอร์ด | 0.028 | 0.050 |

**สาเหตุที่เป็นไปได้**

- นิยามตัวแปรตามต่างกัน — ค่าเฉลี่ยของเขา ~6.7 · พันธมิตรในชุดนี้ 1.46 · นวัตกรรมรวม 9.24
- α ต่างกัน — ของเขา 0.707 · ของชุดนี้ 0.87–1.13 แปลว่าการกระจายของข้อมูลต่างกัน
- จำนวนเทอมต่างกัน — ของเขา 31 · ของชุดนี้ 21–22 แปลว่ามีตัวควบคุมเพิ่ม
- อาจใช้ตัวอย่างหรือการทำความสะอาดข้อมูลคนละชุด

**ต้องเทียบ data dictionary และ do-file กันก่อนสรุป** — ระบบนี้ไม่แก้ตัวเลขให้ตรงกันโดยไม่รู้สาเหตุ
หมายเหตุนี้แสดงอยู่ในแถบข้าง "เกี่ยวกับโมเดล" ของตัวระบบด้วย

## 🧮 คณิตศาสตร์ที่ใช้

```
E[OI]  = exp( β₀ + Σ βₖ·(xₖ − x̄ₖ) + FE(อุตสาหกรรม) + FE(ปี) )
Var(η) = xᵀ · V · x     →     95% CI ของค่าเฉลี่ย = exp( η ± 1.96·√Var(η) )
90% ช่วงพยากรณ์ค่าจริง  = ควอนไทล์ที่ 5 และ 95 ของ NegBinom(μ, α)
```

- **Negative Binomial** — ตัวแปรตามเป็นข้อมูลนับ มีศูนย์ 46% และกระจายเกิน (α ≈ 1.09–1.17)
- ตัวแปรทุกตัว **mean-center** ก่อนเข้าสมการ → ตีความ main effect ได้ตรงแม้มี interaction
- **CI ของค่าเฉลี่ย** ≠ **ช่วงพยากรณ์ค่าจริง** — ระบบแสดงทั้งสองแยกกัน เพราะตอบคนละคำถาม
- เตือนอัตโนมัติเมื่อค่าที่กรอกอยู่นอกเปอร์เซ็นไทล์ 5–95 ของข้อมูลจริง (กัน extrapolation)

### ความแม่นจากการทดสอบนอกกลุ่มตัวอย่าง (391 บริษัท-ปี)

| ตัวชี้วัด | ชุดโมเดล A | ชุดโมเดล B | อ่านอย่างไร |
|---|---|---|---|
| Spearman | 0.260 | **0.342** | ความแม่นของการจัดอันดับ |
| c-index | 0.612 | **0.650** | 0.5 = เดาสุ่ม · 1.0 = สมบูรณ์แบบ |
| MASE | 1.090 | **1.076** | ≥ 1 = **ยังไม่ชนะการเดาด้วยค่าปีก่อน** |
| ช่วงพยากรณ์ 90% ครอบคลุมจริง | 95.4% | 94.9% | ใกล้ 90% = ช่วงตั้งไว้พอดี |

> **อ่านตรง ๆ:** MASE ≥ 1 แปลว่าโมเดลยังทำนาย "จำนวน" ได้ไม่แม่นกว่าการเดาด้วยค่าปีก่อนของบริษัทเดียวกัน
> จุดแข็งอยู่ที่การ **จัดอันดับ** (c-index 0.65) ไม่ใช่การทำนายจำนวนที่แม่นยำ — ระบบแสดงข้อความนี้ให้ผู้ใช้เห็นเสมอ

## 🔒 ความเป็นส่วนตัวและข้อจำกัด

1. **ไม่ใช่ความสัมพันธ์เชิงสาเหตุ** — โมเดลบอกว่าบริษัทที่มีโครงสร้างแบบนี้มักมีนวัตกรรมเปิดเท่าไร ไม่ได้บอกว่าเปลี่ยนโครงสร้างแล้วจะได้ผลตามนั้น
2. **วัดการประกาศ ไม่ใช่นวัตกรรมจริง** — ตัวแปรตามนับจากข้อความในรายงานประจำปี
3. **เอกสารฉบับเดียวกัน** — ภาษาผู้บริหารและจำนวนนวัตกรรมมาจากรายงานฉบับเดียวกัน มีความเสี่ยง endogeneity ที่ยังไม่ได้แก้
4. **ห้ามใช้ให้คะแนนบุคคล** — เพศ อายุ และความเชื่อมโยงทางการเมือง เป็นข้อมูลอ่อนไหวตาม **PDPA มาตรา 26** ระบบออกแบบให้ประเมิน**โครงสร้างองค์กร** ไม่ใช่ประเมินตัวบุคคล
5. **ไฟล์ที่อัปโหลดไม่ถูกส่งออกนอกเครื่อง** — อ่านด้วย pdf.js ในเบราว์เซอร์เท่านั้น
6. **ฐานข้อมูลอ้างอิงปกปิดชื่อทั้งหมด** — สแกนแล้ว ไม่มีชื่อบริษัทหรือชื่อบุคคลในไฟล์ใด
7. `.gitignore` กันไฟล์ข้อมูลดิบและตารางถอดรหัสไม่ให้ถูก commit โดยไม่ตั้งใจ
