## 1. ตอนนี้ทำไมยังไม่ต้องมีเซิร์ฟเวอร์

ทุกอย่างที่ระบบทำอยู่ตอนนี้ทำงานในเบราว์เซอร์ของผู้ใช้ล้วน ๆ — อ่าน PDF นับคำ คำนวณ
Negative Binomial สร้างช่วงความเชื่อมั่น จัดอันดับ ออกรายงาน ไม่มีขั้นตอนไหนต้องใช้เครื่องแม่ข่ายเลย

ข้อดีที่จะเสียไปถ้าย้ายขึ้นเซิร์ฟเวอร์
- **ความเป็นส่วนตัว** ตอนนี้ไฟล์ของผู้ใช้ไม่เคยออกจากเครื่อง ถ้ามีเซิร์ฟเวอร์ ไฟล์จะถูกส่งขึ้นไป
  ซึ่งเปลี่ยนสถานะทางกฎหมายทันที — กลายเป็นการเก็บรวบรวมข้อมูลตาม PDPA ต้องมีนโยบายความเป็นส่วนตัวและฐานการประมวลผล
- **ความเร็ว** ไม่มี round-trip ตอนนี้เลื่อน slider แล้วตัวเลขเปลี่ยนทันที
- **ต้นทุนศูนย์และไม่มีวันล่ม** GitHub Pages เป็น static hosting

## 2. เมื่อไหร่ถึงควรย้าย

| สัญญาณ | เหตุผล |
|---|---|
| ต้องเก็บผลการประเมินไว้ข้ามเครื่อง / ข้ามคน | ต้องมีฐานข้อมูล ซึ่งต้องมีเซิร์ฟเวอร์ |
| ต้องมีบัญชีผู้ใช้และสิทธิ์การเข้าถึง | เบราว์เซอร์อย่างเดียวทำไม่ได้ |
| ต้องเชื่อมข้อมูลสดจาก SETSMART / ก.ล.ต. | ต้องมีที่เก็บ API key ที่ผู้ใช้มองไม่เห็น |
| โมเดลใหญ่เกินกว่าจะฝังในไฟล์เดียว | ตอนนี้ทั้งระบบ 2.85 MB ยังห่างจากขีดจำกัดมาก |
| ต้องรันโมเดลที่เขียนด้วย R หรือ Stata **แบบสด** | แต่ทางลัดคือ **ไฟล์สัญญาโมเดล** — ดู `spec/` ซึ่งแก้ปัญหานี้ได้โดยไม่ต้องมีเซิร์ฟเวอร์ |

## 3. ไฟล์ที่เตรียมไว้แล้วในโฟลเดอร์นี้

| ไฟล์ | ใช้กับ |
|---|---|
| `Dockerfile` | ทุกเจ้าที่รับ container (Render, Railway, Fly.io, Google Cloud Run) |
| `Procfile` | เจ้าที่ใช้ buildpack แบบ Heroku |
| `render.yaml` | Render — ย้ายไปไว้ที่รากของ repo ก่อนใช้ |
| `railway.json` | Railway |
| `fly.toml` | Fly.io |
| `.dockerignore` | กัน `data/` ไม่ให้ติดเข้า image โดยไม่ตั้งใจ |

## 4. ขั้นตอนจริงเมื่อพร้อม (Render · ใช้เวลาราว 15 นาที)

1. `git mv deploy/render.yaml render.yaml` แล้ว push
2. สมัคร render.com → **New → Blueprint** → เลือก repo นี้
3. Render อ่าน `render.yaml` เอง กด **Apply** แล้วรอ build ครั้งแรกราว 5–8 นาที
   (statsmodels กับ pandas ต้องคอมไพล์ ครั้งต่อไปจะเร็วขึ้นเพราะมี cache)
4. ได้ URL หน้าตา `https://promosignal-dss.onrender.com`
5. ตรวจว่ารอดจริงด้วย `curl https://<url>/api/health` ต้องได้ `{"ok": true, ...}`

**ข้อจำกัดของแผนฟรีที่ต้องรู้ก่อนนัดสาธิต**
เครื่องจะหลับเมื่อไม่มีคนใช้ประมาณ 15 นาที คำขอแรกหลังหลับใช้เวลา 30–60 วินาที
ถ้าจะสาธิตให้กรรมการดู **ให้เปิดหน้าเว็บทิ้งไว้ก่อนเริ่มประชุมสัก 1–2 นาที**
หรือย้ายไป Fly.io ที่หยุด/เริ่มเครื่องเร็วกว่ามาก

## 5. สิ่งที่ห้ามลืมตรวจก่อน deploy

- [ ] `data/` ไม่ติดเข้า image — ยืนยันด้วย `docker run --rm promosignal ls /app` ต้องไม่มีโฟลเดอร์ `data`
- [ ] `.gitignore` ยังบล็อก `panel_clean.csv`, `panel_scored.csv`, `firm_key_CONFIDENTIAL.csv` อยู่
- [ ] ถ้าเปิดรับอัปโหลดไฟล์บนเซิร์ฟเวอร์ ต้องเพิ่มนโยบายความเป็นส่วนตัวและกำหนดว่าลบไฟล์ทิ้งเมื่อไหร่
- [ ] จำกัดขนาดไฟล์อัปโหลด (แนะนำ 30 MB) ไม่งั้นแผนฟรีจะหน่วยความจำเต็ม
- [ ] เปิด HTTPS บังคับ (ทุกเจ้าที่ระบุไว้ข้างบนเปิดให้อัตโนมัติ)

## 6. ทางเลือกที่ถูกกว่าและง่ายกว่าการมีเซิร์ฟเวอร์

ถ้าเหตุผลเดียวที่อยากมีเซิร์ฟเวอร์คือ *"อยากให้โมเดลที่ทีมสถิติฟิตใน R ใช้ได้บนเว็บ"*
**ไม่ต้องมีเซิร์ฟเวอร์** — ใช้ไฟล์สัญญาโมเดลใน `spec/` แทน
ฟิตใน R หรือ Stata → ส่งออกเป็น `model.json` → ลากเข้าเว็บ → ทุกหน้าจอเปลี่ยนไปใช้สมการชุดนั้นทันที
วิธีนี้ไม่ส่งข้อมูลดิบออกจากเครื่องทีมสถิติเลย ซึ่งปลอดภัยกว่าการมีเซิร์ฟเวอร์เสียอีก
